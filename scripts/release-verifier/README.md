# Release verifier library

`verify_release` is a Linux-only disabled, non-publishing entry point. It always rejects and exposes neither a callback nor verified output. There is no production trust anchor, approved AppRun reference, runtime key override, CLI, publisher, or release-gate integration. Merely supplying policy values cannot enable the implementation: the experimental engine is compiled only in tests, and an independently reviewed resource-isolated parser and controlled consumer are also necessary.

The test-only prototype verifies a detached Ed25519 signature on a bounded canonical manifest binding a fixed version, commit, five ordered exact paths, sizes and SHA-256 digests. It checks directory entries and descriptor identities, copies candidates into sealed memfds, hashes those snapshots and checks an experimental AppRun reference before invoking a test callback. This callback can still reopen paths; the prototype does not enforce a production consumer contract. Test keys and the experimental reference are not production trust material.

The prototype requires a trusted, quiescent staging directory: identity rechecks are not an atomic filesystem snapshot and cannot prevent transient substitution or in-place modification during verification. Sealed snapshots preserve the validated bytes. Signed size limits are 512 MiB per candidate and 1 GiB total, plus parser and process overhead. The parser has no enforced CPU, wall-time, or complete memory limit; availability against hostile inputs is not established. Approved independent AppRun provenance, production trust provisioning, enforceable resource isolation, a controlled consumer and independent security review remain prerequisites to any production integration.

An independent `squash-worker-prototype` binary demonstrates resource limits and a child deadline but is **not integrated** with this library or release gate. Its executable identity is not pinned, opening/copying input is outside its deadline, and it is not a security sandbox. It must not be used as production verification; authentication and independently approved reference comparison are not provided by the binary.

Run `cargo test --locked` and `cargo test --locked --offline`. The ignored `real_candidates_end_to_end` test uses an ephemeral test signing key and copies the release candidates at its hardcoded repository-relative path to private scratch; it is opt-in due to storage and memory requirements. Check the actual source generation before invoking it. This test does not approve or publish artifacts.
