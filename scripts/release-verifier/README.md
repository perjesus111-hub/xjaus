# Release verifier library

`verify_release` is a Linux-only, non-publishing library entry point. It currently **always rejects** because both the production Ed25519 trust anchor and independently approved AppRun digest are absent. There is no runtime key override, CLI, publisher, or release-gate integration. Test keys and the experimental AppRun digest are not production trust material.

Once a separately reviewed source change supplies both policy values, the engine verifies a detached Ed25519 signature on a bounded canonical manifest before opening or copying candidate files. The manifest binds the fixed version, commit, five ordered exact paths, sizes, and SHA-256 digests. It checks directory entries and symlink-resistant descriptor identities, copies each candidate into a sealed memfd, hashes those exact snapshots, checks the AppRun reference, and only then calls the consumer with those same five descriptors. Consumers must seek to the desired offset and must not reopen candidate paths.

The caller must provide a trusted, quiescent staging directory descriptor: identity rechecks are not an atomic filesystem snapshot and do not prevent transient substitution or in-place modification during verification. The immutable snapshots remain the bytes validated by the verifier. The caller is responsible for sufficient memory/storage quota; nominal signed limits are 512 MiB per candidate and 1 GiB total, plus parser and process overhead. No sandbox, CPU timeout, or complete memory bound on the third-party SquashFS parser is provided. Availability against hostile inputs is not established. A separately reviewed AppRun provenance, trust provisioning, resource isolation, and security review remain prerequisites for production use.

Run `cargo test --locked` and `cargo test --locked --offline`. The ignored `real_candidates_end_to_end` test uses an ephemeral test signing key and copies the existing local release candidates to private scratch; it is opt-in due to substantial storage and memory requirements. It does not approve or publish those artifacts.
